# 点击精度优化调研（一次点准小图标）

调研日期：2026-11-02
调研方式：4 路并行联网调研（合计 100+ 次搜索与文献抓取），聚焦工具与程序侧——不新增 OCR、不上检测模型（OmniParser/UI-TARS 等均排除）。
对应痛点：AI 点击 16~24px 小图标（侧栏图标排、工具栏）第一击常偏 10~40px，要靠落点放大图修正后第二击才准。

---

## 一、先拆误差源：为什么点不准

| 环节 | 实测/文献量级 | 判定 |
|---|---|---|
| 坐标换算与鼠标注入 | ±2px（我们实测） | 不是瓶颈 |
| 模型视觉定位（16~24px 小图标） | 偏 10~40px | **主要瓶颈** |
| 格子读数误差 | ox/oy ±5 单位 ≈ ±5px | 次要 |

文献对这个瓶颈的解释非常一致：

1. **小图标在模型眼里"不足一个感知单元"**。主流 VLM 视觉编码器按约 14px 的 patch 切块，16~24px 图标在整屏截图里只占 1~2 个 patch，细节不可逆丢失（"分辨率诅咒"，V* 论文）。ScreenSpot-Pro 基准（目标平均只占屏幕 0.07%）上，GPT-4o 命中率 0.8~1.1%、Claude Computer Use 17.1%、最强的专用模型也只有 18.9~43.6%；**图标类目标普遍比文本类差 12~20 个百分点**（OS-Atlas：文本 28.1% vs 图标 4.0%）。微软 UI-E2I-Synth 官方确认"小元素+有限分辨率是首要失败因素"。
2. **OSWorld 的失败分析：550 个失败任务里超过 75% 存在鼠标点击不准，是最常见错误**；且模型看不见自己点歪时会出现"反复误点+环境被弄乱"的级联。
3. 结论：第一击偏 10~40px 不是我们实现烂，是当前范式下的预期行为；文献里对症且收益最大的药，是**裁剪放大（crop-and-zoom）**——见下。

---

## 二、四路调研核心结论

### 1. 让模型输出更准（提示词/输出格式层）

- **输出 bbox 取中心比直接给点准**：框的对边约束自带平滑，等价于内插多次采样。GLM-4.5V/4.6V 的原生输出分布就是"宽高归一化 0~1000 的 bbox + 官方框 token"，官方预期用法即取框中心；其 GUI grounding 训练数据有 1.4 亿+ 条，RefCOCO 均值 91.5。
- **裁剪放大是文献里最大的单一杠杆**（零训练）：
  - ReGround：第一次定位后在预测点周围裁 512/768/1024px 放大重定位，25.1→40.2（+15pp），1024px 后饱和；
  - ScreenSeekeR 递归裁剪搜索：18.9→48.1（+29.2pp）；
  - Mark-Grid"裁剪后重铺网格再预测"：Gemini-Flash 在 ScreenSpot-v2 从 5.5%→72.1%。
  - 机理（ICLR 2025《MLLMs Know Where to Look》）：**模型答错时注意力其实已在正确区域，瓶颈是感知分辨率而非"找不到"**——把局部放大到模型原生输入分辨率即可。换算到我们：995px 宽截图里 20px 图标经 patch 化后不足 1 个 token；裁 384px 区域放大后同一图标 64px、跨 4~5 个 patch，这是数量级差异。
- **提示词三步定位**（UI-TARS 官方模板同款）：先一句话描述目标外观特征 → 报出目标四周参照物交叉验证 → 最后给坐标。注意思考要短——GUI-G1 发现长思考会造成"坐标漂移"。
- **指令文本放在图片之前**：Anthropic 官方明说"目标描述先于图像处理能提升点击精度"（零成本）。
- **采样投票**：温度 0.5、K=4~8 次采样，多个 bbox 中心取共识/几何中位；小图标场景收益最高（+6.3pp），64 次才饱和，工程取 4~8 次即可，只在小目标/首击失败时启用。
- **网格辅助是把双刃剑**（对我们最重要的警示）：Mark-Grid 类脚手架对"没有 grounding 特训的通用模型"收益巨大（GPT-4o 从 20.8%→63%，Claude 从 22.8%→67.8%），**但对 grounding 特训过的模型反而有害**——Qwen2-VL-7B 从 47.6% 掉到 28.4%，因为网格改变了模型预训练学到的坐标分布。我们的截图画格方案属于哪一类，必须 A/B 实测。

### 2. 截图标注工程（程序画图层）

- **网格参数有甜点区**：Grid-Augmented Vision 论文的系统消融——黑色 1px、透明度 0.3、**9×9 粒度**最佳（IoU 0.27→0.56）；3×3 太粗、20×20/30×30 明显退化；透明度 0.1 或 0.5 以上都更差。
- **对我们方案的直接警示**：我们是 10×10 大格 + 每格 4×4 细分 = 细线间距约 25px，等效 40×40 网格，远超甜点区；而且 **25px 间距的细线恰好从 16~24px 小图标身上穿过去**——细分标尺可能在帮倒忙。建议细分降级为低透明度虚线（alpha 0.15~0.2）或只画格边刻度（tick）不在格内拉通线。
- **标记回显的正确姿势**（See, Point, Refine 论文，与我们落点放大图直接对标）：红色半透明十字、尺寸约图像宽高 5%、**每次画在干净截图上不累积**、配文"Last attempt: (x,y)"并显式要求模型"推理十字与目标的相对位移后给修正量"。实测二击准确率 20.6%→38.1%、平均偏差 80→57px——验证了我们已有方向，但它只是"第二击变准"，要"一击就准"还得靠点击前的裁剪放大。
- **格号样式**：显式数字刻度优于纯符号索引；轴线+网格组合最好；标签加反色描边防碰撞（SoM 的"距离变换找空白点"算法可程序化）。
- **整格化**：995px 宽导致格宽 99.5px 非整数，模型心算小数易错；画布 pad 到整百使格宽为整数。
- **DPI 陷阱**：进程必须 DPI-aware（我们已做）；125%/150% 非整数缩放下坐标会有累积漂移，截图与点击必须同源物理像素。

### 3. 程序侧校验环（不依赖模型）

- **经典图像处理做"落点吸附"**（整个调研里性价比最高的发现）：SikuliX 的本质就是 OpenCV matchTemplate（阈值 0.7 返回最佳位置），PyAutoGUI 的 locateCenterOnScreen 返回"左上角+半宽高=图标中心"，Airtest 同款思路是国内游戏自动化标配。做法：在模型粗坐标 ±32~48px 的 ROI 里做模板匹配/连通域质心（`connectedComponentsWithStats` 直接给每个连通域包围盒+质心，可按"距粗坐标最近"选域），把 10~40px 的粗偏差直接吸附到图标中心，亚像素精修（cornerSubPix）可到 <1px。全程毫秒级、零模型成本。
- **先瞄后打有成熟范式**：MHVF（arXiv 2610.17792）"多假设→局部放大→标注视图内验证打分"，全程免训练，把 Qwen2.5-VL-7B 在 ScreenSpot-Pro 从 23.6% 提到 53.6%；且证明"瞄准+确认"可以压缩在一次推理内。工程折中：程序画好标记的局部放大图立即二次询问，问题极小化（只答"中/偏X方向几像素"），token 和延迟都小。
- **hover 探测**：RPA（UiPath/Power Automate）都把悬停做成独立动作原语；hover 态是 UI 的标准契约（NN/g），"hover 后区域像素有 diff ⇒ 这是活目标，无变化 ⇒ 换点"。SikuliX 的 onChange 证明该量级的区域 diff 极廉价。对图标密集工具栏的消歧价值最高，且零副作用——把"点两次"变成"移一次+点一次"，比点错安全得多。
- **按压态中间帧校验**：mouse down 与 up 之间抓一帧，按钮区域 diff 检测按压高亮——点击瞬间就知道中没中，比等 0.7 秒 settle 快一个量级。
- **落点控件反查**：`WindowFromPoint`（我们已有）之上还可 `AccessibleObjectFromPoint`/`IUIAutomation::ElementFromPoint` 拿"落点控件的名称/类型"——把"偏没偏"升级为"偏到了哪个控件、它叫什么"，修正方向的信息量远大于像素 diff。（注：微信 4.x 屏蔽 UIA，此招对它无效，但对其他应用可用。）
- **修正搜索**：程序侧螺旋/扩展方波搜索（机器人搜救领域的成熟算法）在落点邻域采样+评分自动补点；Self-Operating Computer 的 offset 修正重试同思路。反直觉提醒（tianpan.co）：观测→行动平均 6.51 秒的间隙意味着"偏"很多时候是时序错而非定位错——重试前先重新观测，不要盲修坐标。
- **系统级加固**：SendInput 绝对坐标要用微软官方取整公式 `x * (65535/(w-1)) + 0.5`（朴素 `x*65536/w` 整除丢精度）；SetCursorPos 直收物理像素无量化误差；双击间隔按 `GetDoubleClickTime()` 兜底。

### 4. 工具/参数/回执设计（各家 computer-use 对比)

- **坐标参数设计**：Claude 用缩放截图上的绝对像素（客户端存缩放因子换算回）；Gemini 用 0~999 归一化；Qwen2.5-VL 从归一化改成**原图绝对像素**后 ScreenSpot-Pro 从 1.6%→43.6%（官方归因"真实尺度"）。**没有跨格式官方对照**，但两级坐标系有强先例：Mark-Grid（8×8 网格+格内细化）、PySC2 的 screen/minimap 双空间。**反面教训**：LLM-PySC2 报告 LLM 会混淆两个坐标空间——两级参数必须"两套标号同图叠加+回执回显换算后像素"才能防混淆。
- **两级坐标系消融结论**（arXiv 2509.11548）：有效脚手架三要素 = 显式性、融合性、粒度均衡；显式数字坐标优于符号索引；轴线+网格组合最好；8×8~10×10 是被验证的甜点区（我们 10×10 主格没选错，错的是 4×4 细分密度）。
- **回执设计**：Anthropic 官方"非截图动作回执一句 OK 就够"，但 `cursor_position` 工具专门回显坐标；Playwright MCP 点击后回无障碍快照让模型从文本验证；OSWorld 的反面教材（>75% 失败含点击不准、模型看不见落点导致级联误点）论证了"回执必须让模型看见落点"。**没有现成消融证明回执字段省几轮，但方向证据一致。**
- **Anthropic 官方点击诊断表**（直接可用）：单方向固定偏移=缩放没换算；大致对但差一点=目标太小被降采样糊掉→开 zoom/保纵横比；点到邻近元素=指令含糊→提示里加位置描述。官方建议思考预算 medium/high、避免 max。
- **批量动作**：官方语义"按序执行、首败即停"，应用侧可主动在批量末尾附截图省一轮。

## 三、根因判定（针对我们系统的三个具体判断）

1. **主因：小图标在模型感知里不足一个 patch + 我们"先点后看"的时序**。20px 图标在 995px 截图里只占 2% 宽度，patch 化后不足 1 个 token；我们现在的落点放大图是"事后取证"，而文献最大杠杆是"事前裁剪放大"。方向需要从"点了再修"往"瞄好了再打"移。
2. **嫌疑：4×4 细分标尺可能干扰识别**。25px 间距的细线从小图标身上穿过，且等效 40×40 网格远超 9×9 甜点区。低成本 A/B：细分线降透明度/改虚线/改刻度 tick，对比小图标首击命中率。
3. **待验证：row/col/ox/oy 两级格式是否适配 GLM-5.3-flash**。GLM-4.5V/4.6V 系的原生分布是 0~1000 bbox；两级格式有先例支撑但也可能负收益——A/B 实测，不要靠猜。

## 四、方案（按"两击变一击"的预期收益排序）

### P1 先瞄后打：小目标两段式定位（文献最大杠杆，+15~29pp）

对"小图标/密集目标"改变交互时序：模型第一次只报目标在哪一格（row/col，粗定位）；程序立即回传**该格的 3~4 倍裁剪放大图（裁剪短边约 384~512px，图内重铺细标尺，并标注裁剪区在全图的原点坐标）**；模型在放大图内报格内偏移，程序换算回全图坐标点击。首击前的这一次往返用极小消息（一张小图+一句问话），代价远小于一次错误点击+修正循环。文献依据：ReGround/ScreenSeekeR/Mark-Grid/MHVF 全部指向同一做法。
（注：这与我们把 zoom 融合为"事后取证"的决定部分相反——对**小图标场景**需要恢复"先放大瞄准"，对普通大目标保留事后取证即可。两者并存，按目标大小/置信分流。）

### P2 程序侧落点吸附（经典图像处理，毫秒级零模型成本）

拿到模型粗坐标后，在 ±32~48px ROI 内用 OpenCV 模板匹配/连通域质心找"最近的可交互元素中心"，把坐标吸过去；吸附位移小于阈值（如 3px）说明模型本来就准。可选再叠加 hover 探测（移动不点击，等 300~500ms 区域 diff 确认是活目标）后落点。SikuliX/PyAutoGUI/Airtest 三条成熟产品线背书。注意：吸附失败要回退确认流程，不许瞎吸；对 DPI/主题变化敏感，需灰度+多尺度。

### P3 回执升级：让模型"看见自己的落点+候选"

落点放大图上同时画两个标记：红十字=模型给的坐标，蓝/绿圈=吸附候选中心（P2 的产物）；回执文本回显全部数字："你给 B7 格 (ox=42,oy=30) → 屏幕 (997,335)，命中窗口 X，最近图标中心 (1002,331)（距离 5px）"。第二击的提示词限定为"微调语义"（dx/dy 或格内新偏移，限制单次修正幅度），防止整格重选大漂移（OSWorld 级联误点教训）。参照 See-Point-Refine：红十字按图宽 5% 尺寸、每轮画在干净截图上。

### P4 标注降噪与整格化

细分标尺从"格内 4×4 通线"降级为：透明度 0.15~0.2 的虚线，或只画格边刻度 tick；主格线黑 1px 透明度 0.3（论文最优组合）；行-列标签加反色描边、防碰撞摆放；画布 pad 成整百让格宽为整数（995→1000），消掉小数心算。整体先 A/B 一版"细分减密"看小图标首击率。

### P5 输出格式与提示词 A/B

- A/B 一：现行 row/col/ox/oy vs 让模型直接输出目标的 0~1000 bbox（取中心点击）——对齐 GLM-4.5V/4.6V 原生分布。
- A/B 二：带格截图 vs 无格纯图（小图标场景分开统计）。文献警示：对 grounding 特训模型，网格可能负收益（47.6%→28.4% 的反例）。
- 提示词：三步定位（描述特征→报参照物→给坐标）、指令文本放在图片之前（Anthropic 官方）、小图标专项提示（"目标可能小于 25px 且附近有相似图标，先读懂图标含义再定位"）。

### P6 点击即时校验

mouse down 与 up 之间抓一帧做按压态 diff——点击瞬间即知是否命中可交互元素，不等 0.7 秒 settle；配合现有命中窗口回执，构成"中没中"的双重即时信号。

### P7 采样投票（仅小目标保底）

首击失败或目标 <32px 时，K=4~8 次温度采样、多个 bbox 中心取共识，小图标场景 +6.3pp。成本可控（只在困难场景触发）。

### P8 系统链路加固（一次性体检）

SendInput 归一化用微软官方公式、SetCursorPos 兜底、关闭鼠标加速、双击间隔按 GetDoubleClickTime、DPI 一致性复核（已 DPI-aware，确认 125%/150% 缩放下无累积漂移）。

## 五、推荐落地路线

1. **第一波（本周可做，全是低风险）**：P4 标注降噪 + P3 回执升级（双标记+数字回显+微调语义）+ P5 的提示词部分（三步定位、指令前置）。先跑一个"小图标首击命中率"的基线统计（人工标 20 个小图标目标测首击率），之后每项改动对着这个数比。
2. **第二波（核心，需要你拍板交互时序）**：P1 先瞄后打两段式。这是文献里收益最大的一项，但会改变小图标场景的交互流程（多一次极小往返），并且部分回调我们此前"zoom 融合为事后取证"的决定——建议做成"按场景分流"：普通目标走现流程，小图标/首击失败走两段式。
3. **第三波（程序侧提速，需引入 OpenCV）**：P2 落点吸附 + hover 探测 + P6 按压态校验。这些不依赖模型、毫秒级，但要用真实界面验证吸附的鲁棒性。
4. **穿插**：P5 的两个 A/B、P7、P8。

**验收指标**：自建 20~30 个小图标点击用例，统计"首击命中率"和"平均每目标点击次数"；文献参照：通用模型裸点小图标首击率个位数到 20%，裁剪放大后 40%+，Mark-Grid 式流程可到 70%+——我们的目标是把小图标首击率从当前水平提到 80% 以上、普通目标 95%+。
